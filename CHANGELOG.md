# Changelog

## Unreleased

- Repository skeleton: package, CLI envelope and exit codes, JSON Schemas, CI, design dossier and MVP specification.
- Discovery, components and runtime (P1.3): `peo.discovery.discover()` finds components, stacks, languages, code paths, `monorepo`, `multi_component` and where each component's commands run (`host` or `docker:<service>`); `peo.runner`, the injectable command runner. Acceptance test A1.3 passes.
- Discovery, commands and conventions (P1.4): commands per component (`typecheck`, `test`, `lint`, `build`, `e2e`, `format`) prefixed by the runtime, the aggregated `verify`, branch and commit conventions measured from git history (merges excluded), `kind`, `git`, `ci` and the gaps `no-ci`, `no-verify`, `no-remote`, `no-tests:*`, `no-lint:*`. Acceptance test A1.4 passes.
- Discovery, documentation and drift (P1.5): `docs` (README, `CLAUDE.md` class, `AGENTS.md`, handoff, decisions folder), tools announced by the docs (`intent_from_docs`, from a table of the initial catalog), documentation drift D1 to D4 with fixed messages, and the gaps `no-agents-md` and `no-adr`. Acceptance test A1.5 passes; only A1.1 (full profile) remains.
- Discovery, signals, sensitive surfaces, present tools and metrics (P1.6): the four selection signals, `sensitive` (secret files with variable names only, databases from compose images, dumps, log directories; no secret value ever in an output, NF14), catalog tools already present (`present_tools`, provisional `detect.toml`) and `metrics`. The `fx-split-stack` fixture gains an untracked `backend/.env` with fake values. Acceptance tests A1.8 and the Discovery part of A14.2 pass, and so does A1.1: the whole profile equals the golden file (only `generated`, written by `peo discover --write`, is left for P1.7).
- `peo discover` command (P1.7): `--json`, `--write` (`.peo/profile.json`, sorted, ASCII JSON, written atomically and synced to disk, mode `0666` minus the umask, `generated` in UTC; `.peo/` is excluded from Discovery so writing it never changes the next profile) and `--project`; the root is `--project`, else the git root of the current directory, else the current directory. Warnings and errors go to the envelope and, one line each prefixed by their code, to stderr. New error codes `E_PROJECT_NOT_FOUND` (exit 2) and `E_WRITE_FAILED` (exit 1). Every JSON envelope now has sorted keys. Acceptance tests A1.1 (through the command), A1.2, A1.6 and A1.7 pass.
- Profile schema: a bare root component (spec 12 rule 11, new or manifest-less repository) may have no ecosystem and no code path; `peo discover --write` on a new repository now writes a valid profile.
- Claude Code Inventory (R2): `peo.inventory.inventory()` reads Claude Code settings (managed, local, project and user scopes), `.mcp.json`, `managed-mcp.json` and `claude plugin list --json`, and returns hooks, permission rules, sandbox flags, plugins, MCP servers and the form of every `env`, `headers` and `url` value, with an explicit state for every source, and never a value; `declared()` returns the tracked project declarations. Acceptance tests A3.1 to A3.11 (A3.4 removed).
- New schema `inventory.schema.json` (`data.inventory` of `peo status`, never written to disk).
- NF14 in two regimes: a closed list of allowed fields for the Inventory output; the current "no value" rule for every other output.
- H27: selection reads only the tracked project declarations; the Planner vetoes an alternative backbone or a `privacy.masking` provider active elsewhere (`E_BACKBONE_CONFLICT`, exit 6).
- Catalog entry schema change: `[detect].mcp` is now an array of `{kind = "package" | "host" | "command", value}` objects instead of strings.
- Profile schema: `present_tools[].via` is restricted to `dev-dependency` and `file`, the only values Discovery emits.
- Discovery fixes: a dump that is a broken symbolic link no longer makes `peo discover` fail (it is ignored); `flask` is now listed as a server stack in spec 12, as the code already did.
- Known debt: `Schema.from_dict` keeps a deep copy of the schema; unit tests for the Go, Rust, JVM, Ruby and `requirements*.txt` manifest readers.
- CI/CD: `ci`, `release` (GitHub release, PyPI trusted publishing behind a switch), `codeql`, Dependabot; `tools/release.py` for version consistency and release notes.
